# Production runbook (Phase 0 only)

This stack is still the Phase 0 thin-core slice: Node core, PostgreSQL with RLS,
a static dev UI, Keycloak identity, and append-only audit. It is not a full
CCaaS deployment. WhatsApp, email, voice, AI flows, Temporal, NATS, and the
full React/Carbon inbox are out of scope here.

## Host layout

- Apache runs on the host and owns 80/443. It terminates TLS and is the only
  public entry point.
- Docker publishes only loopback ports: core on `127.0.0.1:18080`, Keycloak on
  `127.0.0.1:18081`. Ports 8080/8081 on this host are already taken by
  ISPConfig Apache and another service, so they are not used.
- The dev override that also uses 18080/18081 must be stopped before bringing
  up this stack; the two stacks cannot share those loopback ports.
- Keycloak listens on `/auth`, so its browser URLs are
  `https://ofcf.hostedservices.cloud/auth/realms/ccaas/...`.
- The realm's `frontendUrl` is `https://ofcf.hostedservices.cloud/auth`. This
  is required because `KC_HOSTNAME_PATH` alone does not add `/auth` to the
  discovery document.
- Core's issuer is exactly
  `https://ofcf.hostedservices.cloud/auth/realms/ccaas`; JWKS is fetched
  internally over `http://keycloak:8080/auth/realms/ccaas/protocol/openid-connect/certs`.

## DNS and TLS

1. At Cloudflare (the zone's nameservers are Cloudflare, not the registrar),
   add an `A` record for `ofcf` pointing at the origin IP.
2. Choose one TLS path:
   - Cloudflare proxied (orange cloud): install a Cloudflare Origin CA
     certificate and key on host Apache. Public TLS is terminated by Cloudflare.
   - DNS-only (grey cloud): issue a normal certificate with certbot webroot,
     since Apache already owns 80/443. HTTP-01 through an orange-cloud proxy is
     unreliable; use DNS-01 or Origin CA instead.
3. Point `SSLCertificateFile` / `SSLCertificateKeyFile` in the vhost below at the
   chosen certificate.

If Cloudflare proxies traffic, Apache sees Cloudflare IPs in `REMOTE_ADDR`.
Rate limiting and audit source IP will reflect that until Cloudflare IP
handling is added.

## Environment

    cp .env.production.example .env.production
    openssl rand -hex 24   # run once per password below

Fill `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`, `WIDGET_TOKEN`,
`KEYCLOAK_DB_PASSWORD`, `KEYCLOAK_ADMIN_PASSWORD`, `AGENT_PASSWORD`, and
`ADMIN_PASSWORD`.
Passwords must match `[A-Za-z0-9_.-]+` (the Postgres init SQL and realm
entrypoint validate this, and `DATABASE_URL` needs URL-safe values). Keep
`PUBLIC_BASE_URL` without a trailing slash. `.gitignore` ignores `.env.*` and
re-includes `.env.production.example`; still check `git status` before
committing anything.

`KEYCLOAK_ISSUER`, `KEYCLOAK_JWKS_URL`, `KEYCLOAK_TOKEN_URL`,
`KEYCLOAK_AUDIENCE`, `PUBLIC_BASE_URL`, `TRUST_PROXY`, and `RATE_LIMIT_ENABLED`
are all set on the core container by the compose file.

## Bring up

    docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
    docker compose --env-file .env.production -f docker-compose.prod.yml ps

Postgres init scripts only run on an empty data volume. Use a fresh
`postgres_data` volume for the first prod bring-up; on an existing volume the
seeded passwords below are not applied and must be rotated manually.

On first volume init Postgres applies `db/schema.sql`, then a generated init
file sets the `app_user` password, creates the separate `keycloak` role/database,
inserts the Acme/Globex tenant rows, and seeds one widget token hashed from
`WIDGET_TOKEN`. `db/seed.sql` is deliberately not mounted in production, so no
dev token exists there. The UI no longer ships a default widget token. Keycloak
imports the rendered realm from `keycloak/realm-prod.json.template`; realm keys
are generated by Keycloak on first import.

The realm import only applies to an empty Keycloak database. Changing seeded
user passwords later requires the Keycloak admin console or a manual reimport.

## Host Apache vhost

Enable `proxy`, `proxy_http`, `headers`, `ssl`, and `rewrite`, then use this as
a starting point:

```apache
<VirtualHost *:80>
    ServerName ofcf.hostedservices.cloud

    Alias /.well-known/acme-challenge/ /var/www/certbot/.well-known/acme-challenge/
    <Directory /var/www/certbot/.well-known/acme-challenge/>
        Require all granted
    </Directory>

    RewriteEngine On
    RewriteCond %{REQUEST_URI} !^/\.well-known/acme-challenge/
    RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]
</VirtualHost>

<VirtualHost *:443>
    ServerName ofcf.hostedservices.cloud

    SSLEngine on
    SSLCertificateFile /etc/ssl/origin/ofcf.crt
    SSLCertificateKeyFile /etc/ssl/origin/ofcf.key

    ProxyPreserveHost On
    ProxyAddHeaders Off

    RequestHeader set X-Forwarded-Proto "https" early
    RequestHeader set X-Forwarded-Host "expr=%{HTTP_HOST}" early
    RequestHeader set X-Forwarded-For "expr=%{HTTP:CF-Connecting-IP} || %{REMOTE_ADDR}" early

    ProxyPass /auth/ http://127.0.0.1:18081/auth/
    ProxyPassReverse /auth/ http://127.0.0.1:18081/auth/

    ProxyPass / http://127.0.0.1:18080/
    ProxyPassReverse / http://127.0.0.1:18080/
</VirtualHost>
```

The `/auth/` block must come before `/`. It preserves the `/auth` prefix on the
backend because Keycloak runs with `KC_HTTP_RELATIVE_PATH=/auth`; proxying to
`http://127.0.0.1:18081/` without that prefix would make Keycloak return 404.
Keep both loopback targets reachable only from the host firewall; do not add
wildcard publishes to the compose file.

## Health checks

    curl -fsS http://127.0.0.1:18080/healthz
    curl -fsS https://ofcf.hostedservices.cloud/healthz
    curl -fsS https://ofcf.hostedservices.cloud/api/config
    curl -fsS https://ofcf.hostedservices.cloud/auth/realms/ccaas/.well-known/openid-configuration | grep issuer

The issuer in the discovery document must be
`https://ofcf.hostedservices.cloud/auth/realms/ccaas`. Logs:

    docker compose --env-file .env.production -f docker-compose.prod.yml logs -f core keycloak postgres

Container health lives on internal networks; do not publish Keycloak's port
9000 management interface.

## Backup and restore

The repo includes `scripts/backup.sh` and `scripts/restore.sh`. They call
`pg_dump` and `pg_restore` from the host and need a host-reachable `ADMIN_DATABASE_URL` (or
`DATABASE_URL`). Production publishes no database port, so the reliable path is
to run the dump inside the postgres container:

    mkdir -p backups
    stamp=$(date -u +%Y%m%dT%H%M%SZ)
    docker compose --env-file .env.production -f docker-compose.prod.yml exec -T postgres pg_dump -Fc -U postgres -d ccaas > "backups/ccaas-$stamp.dump"
    docker compose --env-file .env.production -f docker-compose.prod.yml exec -T postgres pg_dump -Fc -U postgres -d keycloak > "backups/keycloak-$stamp.dump"

Restore after stopping core and keycloak, and take a volume snapshot before
schema changes:

    docker compose --env-file .env.production -f docker-compose.prod.yml stop core keycloak
    docker compose --env-file .env.production -f docker-compose.prod.yml exec -T postgres pg_restore --clean --if-exists --exit-on-error -U postgres -d ccaas < backups/ccaas-STAMP.dump
    docker compose --env-file .env.production -f docker-compose.prod.yml exec -T postgres pg_restore --clean --if-exists --exit-on-error -U postgres -d keycloak < backups/keycloak-STAMP.dump
    docker compose --env-file .env.production -f docker-compose.prod.yml start core keycloak

If a host-reachable admin URL is available, the scripts can be used directly:

    ADMIN_DATABASE_URL=postgres://postgres:PASSWORD@db-host:5432/ccaas BACKUP_DIR=./backups scripts/backup.sh
    CONFIRM_RESTORE=1 ADMIN_DATABASE_URL=postgres://postgres:PASSWORD@db-host:5432/ccaas scripts/restore.sh backups/ccaas-STAMP.dump

Store dumps off-host; never keep them in the repo. The `.gitignore` already
ignores `backups/`.

## Rollback

    docker compose --env-file .env.production -f docker-compose.prod.yml down
    # restore the previous compose/env revision and, if the schema changed, the volume snapshot
    docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build

`down` without `-v` keeps named volumes. If a schema migration ran, restore the
matching volume snapshot instead of starting an older image against a newer
schema.

## Remaining gaps

- No CI deploy pipeline; updates are manual on the host.
- No product channels or full inbox UI (Phase 0 scope).
- No secret manager; secrets live in `.env.production`.
- Rate limiting is enabled by default; tune `RATE_LIMIT_*` before large traffic.
- No scheduled backups; the scripts above need a host-reachable admin URL.
- Keycloak admin console is reachable under `/auth/admin/`; restrict it at
  Apache if it must not be public.
- The production widget token is hashed in the DB but must still be pasted into
  the UI; do not embed it in static assets.
